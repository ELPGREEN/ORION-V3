 1. VISAO GERAL DA ARQUITETURA
================================================================================

O sistema "Rede Neural Conexao" eh uma plataforma de IA hibrida quantico-
classica para direito brasileiro, operando como um "funcionario sintetico"
recursivo com capacidade de auto-melhoria via loops de feedback.

STACK TECNOLOGICO:
- Frontend: React + TypeScript + Tailwind CSS + shadcn/ui + Vite
- Backend: Supabase (PostgreSQL + Edge Functions + Auth + Storage)
- LLMs: 5 provedores (Gemini, Groq, Anthropic, OpenAI, GitHub Models)
- Embeddings: OpenAI text-embedding-3-small (768 dimensoes)
- PDF: Hugging Face Space (ericsonv12-adv) via Edge Functions
- Busca Web: Perplexity + Firecrawl (fallback)
- Assinatura Digital: ClickSign
- Pagamentos: Stripe

PRINCIPIOS FUNDAMENTAIS:
- Custo zero em licenciamento (100% open-source ou APIs)
- Resiliencia: 3 tentativas com backoff exponencial + fallback entre provedores
- Auto-evolucao: Feedback -> Auto-Aprendizado -> Embeddings -> Evolucao
- Seguranca: RLS em todas as tabelas, LGPD compliance, anti-alucinacao
- Sociedade da Mente: 11 agentes especializados como "cortical columns" (v22.3)
- PRINCIPIO v22: Toda interacao do usuario (chat, editor, dashboard, audiencia, secretaria,
  educacao, busca, treinamento) agora eh multimodal por padrao. Visao e audicao sao
  processadas automaticamente e fundidas com o texto em todos os pipelines.

TAXONOMIA DE REDES NEURAIS UTILIZADAS (v22):
- Feedforward (MLP): Treinamento de especializacoes via Backpropagation
- Recurrent (GRU): Session tracking e inferencia temporal (v16)
- Hopfield Network: Memoria associativa de padroes juridicos (v19)
- Transformer-Based: Todos os LLMs externos (GPT, Gemini, Claude, Llama)
- Graph Neural Network: Message passing entre resultados de busca (v17)
- Competitive Learning: Winner-Takes-All para 12 categorias (v19)
- Mamba/SSM 5-Stream: State Space Model O(n) para Texto + Visao + Audio + Layout + Gestos (v22)
- Cross-Modal Embeddings: Alinhamento contrastivo Texto<>Visao<>Audio<>Gestos (CLIP+HuBERT+MediaPipe) (v22)
- Cross-Attention 5-Way: Flamingo-style + Video-Mamba + Temporal Binding STDP com Gamma Oscillation
  para binding consciente de voz, rosto e gestos (v22)
- Facial & Gesture Recognition: MediaPipe FaceMesh + Pose + InsightFace + YOLO-Face + FER (v22)
- Auditory Stream: Whisper-large-v3-turbo + HuBERT (streaming real-time em todo o sistema) (v22)

FUNDAMENTACAO MATEMATICA (Vaswani et al. 2017):
  Attention(Q,K,V) = softmax(Q * K^T / sqrt(d_k)) * V
  Onde:
  - Q = X * W^Q  (query projection)
  - K = X * W^K  (key projection)
  - V = X * W^V  (value projection)
  - d_k = dimensao das keys (estabiliza gradientes)
  - softmax normaliza pesos de atencao por linha

  MultiHead(Q,K,V) = Concat(head_1, ..., head_h) * W^O
  Onde head_i = Attention(Q*W_i^Q, K*W_i^K, V*W_i^V)

HOPFIELD NETWORK (v19) - ALGORITMO COMPLETO:
  // Memoria associativa com padroes bipolares (-1/+1)
  // Regra de Hebb Generalizada:
  wij = (1/H) * SUM_p(xp_i * xp_j)  // H = numero de padroes

  // Relaxacao assincrona ate estado estavel:
  for each neuron i (random order):
    h_i = SUM_j(w_ij * x_j)  // campo local
    x_i = sign(h_i)           // atualizacao

  // Funcao de Energia (Lyapunov):
  E = -1/2 * SUM_ij(w_ij * x_i * x_j)
  // Monotonicamente decrescente → convergencia garantida

  // Recall via distancia de Hamming:
  d_H(x, p) = (1/N) * SUM_i(1 - x_i * p_i) / 2

COMPETITIVE LEARNING (v19) - ALGORITMO COMPLETO:
  // 12 categorias juridicas
  categories = [constitucional, trabalhista, penal, civil, tributario,
                administrativo, ambiental, consumidor, previdenciario,
                eleitoral, empresarial, familia]

  // Winner-Takes-All:
  for each input x:
    i* = argmax_i(w_i . x)  // neuronio vencedor
    y_i* = 1, y_i = 0 para i != i*

  // Atualizacao Kohonen:
  delta_w_ij = eta * y_i * (x_j - w_ij)
  // Normalizacao para comprimento unitario:
  w_i = w_i / ||w_i||

FUNCOES DE ATIVACAO (ver Secao 32 para catalogo completo):
- sigmoid(v) = 1/(1+exp(-a*v))
- tanh(v) = Math.tanh(v)
- relu(v) = max(0, v)
- leakyRelu(v, alfa=0.01) = v > 0 ? v : alfa*v
- gelu(v) = v * Phi(v) -- usado em BERT/GPT
- swish(v) = v * sigmoid(v) -- usado em Gemini

- softmax(values) -- normalizacao para camada de saida

NEURONIO ARTIFICIAL - CODIGO:
  // y_k = F(SUM(x_i * w_ki) + b_k)
  function neuron(inputs: number[], weights: number[], bias: number): number {
    let sum = bias;
    for (let i = 0; i < inputs.length; i++) {
      sum += inputs[i] * weights[i];
    }
    return sigmoid(sum);  // ou outra funcao de ativacao
  }

ALGORITMOS DE APRENDIZADO IMPLEMENTADOS:

  1. Delta Rule (Widrow-Hoff):
     delta_w = eta * e * x
     // e = (target - output), eta = learning rate

  2. Backpropagation:
     // Camada de saida:
     delta_k = e_k * phi'(v_k)
     // Camada oculta:
     delta_j = phi'(v_j) * SUM_k(delta_k * w_kj)
     // Atualizacao:
     w_ji(n+1) = w_ji(n) + eta * delta_j * y_i + alfa * delta_w_ji(n-1)

  3. Hebbian Learning:
     delta_w_kj = eta * (x_j - x_medio) * (y_k - y_medio)
     // "Fire together, wire together"

  4. Adam Optimizer:
     m_t = beta1 * m_{t-1} + (1 - beta1) * g_t
     v_t = beta2 * v_{t-1} + (1 - beta2) * g_t^2
     m_hat = m_t / (1 - beta1^t)
     v_hat = v_t / (1 - beta2^t)
     w = w - eta * m_hat / (sqrt(v_hat) + epsilon)
     // beta1=0.9, beta2=0.999, epsilon=1e-8

  5. Nguyen-Widrow Initialization:
     beta = 0.7 * n^(1/p)
     // n = neurons in hidden layer, p = neurons in input layer

  6. AdamW (peso decay desacoplado):
     w = w - eta * (m_hat / (sqrt(v_hat) + eps) + lambda * w)

  7. Cosine Annealing com Warm Restarts:
     eta_t = eta_min + 0.5 * (eta_max - eta_min) * (1 + cos(pi * t / T))

TD LEARNING (v13) - ALGORITMO:
  delta_t = r_{t+1} + gamma * V(s_{t+1}) - V(s_t)
  V(s_t) = V(s_t) + alfa * delta_t

  // alfa = 0.1 (V-estimate learning rate)

 10. QUANTUM DEEP LEARNING (QDL)

AMPLITUDE ENCODING - ALGORITMO:
  // |psi> = H x RY(theta) x RZ(theta/2) |0>
  function amplitudeEncode(value: number): number {
    const hadamard = 1 / Math.sqrt(2);                 // H gate
    const ry = Math.cos(value * Math.PI / 2);          // RY rotation
    const rz = Math.cos(value * Math.PI / 4);          // RZ rotation
    return hadamard * ry * rz;
  }

QNN 3-LAYER ARCHITECTURE - ALGORITMO:
  function qnnForward(inputs: number[], params: number[][][]): number {
    let state = inputs.map(amplitudeEncode);

    for (let layer = 0; layer < 3; layer++) {
      // Apply RX, RY, RZ rotations per qubit
      for (let q = 0; q < state.length; q++) {
        state[q] = rx(params[layer][q][0]) *
                   ry(params[layer][q][1]) *
                   rz(params[layer][q][2]) * state[q];
      }
      // CNOT entanglement between adjacent qubits
      for (let q = 0; q < state.length - 1; q++) {
        state[q+1] ^= state[q];  // simplified CNOT
      }
      // BatchNorm + Residual
      state = batchNorm(state);
      state = state.map((s, i) => s + inputs[i]);  // residual
    }
    return sigmoid(mean(state));
  }

VON NEUMANN ENTROPY:
  S(rho) = -SUM(p_i * log2(p_i))

PARAMETER-SHIFT GRADIENT:
  df/dtheta = [f(theta+pi/2) - f(theta-pi/2)] / 2
  // Nativo quantico (sem backprop classico)
  // Aplicado em cada parametro de cada camada

================================================================================
 14. ARQUITETURA TRANSFORMER FORMAL
================================================================================

Referencia: Vaswani et al. "Attention Is All You Need" (2017)

COMPONENTES FUNDAMENTAIS:

1. TOKENIZACAO:
   Texto -> sequencia de tokens (subwords via BPE ou SentencePiece)
   Cada token -> vetor via lookup em embedding table
   Dimensao: d_emb (tipicamente 768, 1024, 4096, 8192)

2. POSITIONAL ENCODING:
   a) Sinusoidal (original 2017):
      PE(pos, 2i)   = sin(pos / 10000^(2i/d_emb))
      PE(pos, 2i+1) = cos(pos / 10000^(2i/d_emb))
   b) RoPE (Rotary Position Embedding) - usado em Llama/Gemini:
      Aplica rotacao 2D em pares de dimensoes
   c) ALiBi (Attention with Linear Biases) - alternativa eficiente:
      Adiciona bias linear ao attention score baseado em distancia
   NOSSO SISTEMA: Usa sinusoidal encoding (v18) no neural-search

3. SCALED DOT-PRODUCT ATTENTION:
   Attention(Q, K, V) = softmax(Q * K^T / sqrt(d_k)) * V

4. MULTI-HEAD ATTENTION:
   MultiHead(Q,K,V) = Concat(head_1, ..., head_h) * W^O
   head_i = Attention(Q * W_i^Q, K * W_i^K, V * W_i^V)
   NOSSO SISTEMA: 7 heads especializados (semantico, keyword, etc.)

5. FEED-FORWARD NETWORK (FFN):
   FFN(x) = phi(x * W1 + b1) * W2 + b2
   Ativacao: ReLU (original), GELU (BERT/GPT), SwiGLU (Llama/Gemini)

6. RESIDUAL CONNECTIONS + LAYER NORMALIZATION:
   Pre-LN (moderno): x + Sublayer(LayerNorm(x))
   NOSSO SISTEMA: Usa residual + LayerNorm no QNN (v16/v18)

7. VARIANTES: Encoder-Only (BERT), Decoder-Only (GPT/Llama/Gemini/Claude),
   Encoder-Decoder (T5)

8. OTIMIZACOES MODERNAS:
   - KV Cache, Flash Attention, GQA, MoE, Sliding Window

 15. TIPOS AVANCADOS DE REDES NEURAIS (28/28 do Asimov Neural Network Zoo)
================================================================================

Referencia: https://www.asimovinstitute.org/neural-network-zoo/
Artigo base: https://iaexpert.academy/2020/06/08/os-tipos-de-redes-neurais/
Todos os 28 tipos classicos estao implementados como modulos ou nos na

REDES IMPLEMENTADAS (28):

--- FEEDFORWARD ---

1. Perceptron (P):
   Modulo: slim_router (SLM Router)
   Funcao: Roteamento rapido de complexidade (low/medium/high)
   Arquitetura: Single-layer threshold unit

2. Feed Forward Network (FFN) / Deep Neural Network (DNN):
   Modulo: llm_core (LLM Core / Transformer)
   Funcao: Backbone principal de geracao de texto
   Arquitetura: Multi-layer com backpropagation + Adam

3. Radial Basis Function Network (RBF):
   Modulo: rbf_gate (RBF Gate)
   Funcao: Gate de roteamento MoE com funcoes de base radial
   Arquitetura: phi(x) = exp(-||x - c||^2 / 2*sigma^2)

--- RECORRENTES ---

4. Recurrent Neural Network (RNN):
   Modulo: temporal_context (Contexto Temporal)
   Funcao: Dependencia temporal entre turnos de conversa
   Equacao: h_t = tanh(W_h * h_{t-1} + W_x * x_t + b)

5. Long Short-Term Memory (LSTM):
   Modulo: episodic_mem (Memoria Episodica)
   Funcao: Retencao de contexto longo prazo com forget gate
   Equacoes: f_t, i_t, o_t gates + cell state c_t

6. Gated Recurrent Unit (GRU):
   Modulo: gru_health (GRU Health Monitor)
   Funcao: Monitoramento de saude dos providers com memoria temporal
   Equacoes:
     z_t = sigmoid(W_z * [h_{t-1}, x_t])       // Update gate
     r_t = sigmoid(W_r * [h_{t-1}, x_t])       // Reset gate
     h_t = (1-z_t) * h_{t-1} + z_t * tanh(W * [r_t * h_{t-1}, x_t])

--- AUTOENCODERS ---

7. Auto-Encoder (AE):
   Modulo: embeddings (Embedding Engine)
   Funcao: Compressao de documentos juridicos para espaco latente 768d
   Arquitetura: encoder(input) -> latent(768d) -> decoder(reconstruct)

8. Variational Auto-Encoder (VAE):
   Modulo: vae_gen (Geracao Variacional)
   Funcao: Geracao de variacoes semanticas de peticoes
   Arquitetura: encoder -> mu,sigma -> z~N(mu,sigma) -> decoder

9. Denoising Auto-Encoder (DAE):
   Modulo: dae_cleaner (DAE Limpeza)
   Funcao: Reducao de ruido em embeddings e OCR de documentos
   Arquitetura: input+noise -> encoder -> latent -> decoder -> clean_output

10. Sparse Auto-Encoder (SAE):
    Modulo: sae_features (SAE Feature Discovery)
    Funcao: Descoberta de features ocultos em datasets juridicos
    Arquitetura: input -> expanded_latent(dim > input_dim) -> sparsity_penalty

--- PROBABILISTICAS / ENERGIA ---

11. Markov Chain (MC):
    Modulo: markov_chain (Cadeia de Markov)
    Funcao: Modelagem de transicoes de estado processual
    Propriedade: P(s_{t+1} | s_t) — sem memoria, apenas estado atual

12. Hopfield Network (HN):
    Modulo: hopfield (Hopfield Memory)
    Funcao: Memoria associativa para recuperacao de padroes juridicos
    Convergencia: Energia E = -0.5 * sum(w_ij * s_i * s_j) minimizada

13. Boltzmann Machine (BM):
    Modulo: boltzmann (Boltzmann Machine)
    Funcao: Estabilizacao de estados de equilbrio no sistema neural
    Arquitetura: Neuronios visiveis + escondidos, energia estoccastica

14. Restricted Boltzmann Machine (RBM):
    Modulo: Integrado no defense/boltzmann
    Funcao: Treinamento eficiente sem inter-conexoes intra-camada
    Treinamento: Contrastive Divergence (CD-k)

15. Deep Belief Network (DBN):
    Modulo: knowledge_base (Base de Conhecimento)
    Funcao: Empilhamento de RBMs para encoding hierarquico de documentos
    Treinamento: Greedy layer-wise pre-training

--- CONVOLUCIONAIS ---

16. Convolutional Neural Network (CNN / DCN):
    Modulo: vlm (Vision-Language Model)
    Funcao: Classificacao de imagens de documentos e OCR
    Arquitetura: Conv filters -> Pooling -> FFN classifier

17. Deconvolutional Network (DN):
    Modulo: deconv_gen (Deconvolucional Generator)
    Funcao: Geracao de imagens a partir de embeddings comprimidos
    Arquitetura: Latent -> Deconv layers -> Full resolution output

18. Deep Convolutional Inverse Graphics Network (DCIGN):
    Modulo: vlm (Vision-Language Model)
    Funcao: VAE com CNN encoder + DN decoder para manipulacao visual
    Capacidade: Gerar variacoes de documentos visuais

--- GENERATIVAS ---

19. Generative Adversarial Network (GAN):
    Modulo: orion_shield (Orion Defense System)
    Funcao: Deteccao de alucinacoes e geracao adversarial para testes
    Arquitetura: Generator vs Discriminator (competitive training)

--- SPIKING / BIOLOGICAS ---

20. Liquid State Machine (LSM):
    Modulo: stdp (STDP Learning)
    Funcao: Spike-Timing-Dependent Plasticity para aprendizado temporal
    Arquitetura: Threshold firing + random connections + memory accumulation

21. Extreme Learning Machine (ELM):
    Modulo: elm_fast (ELM Fast Classifier)
    Funcao: Classificacao rapida sem backpropagation (least squares)
    Vantagem: Treinamento em etapa unica, muito mais rapido

22. Echo State Network (ESN):
    Modulo: Integrado no temporal_context
    Funcao: RNN com conexoes aleatorias para dados nao-digitais
    Treinamento: Sem backpropagation, reservoir computing

--- RESIDUAIS / MEMORIA ---

23. Deep Residual Network (DRN):
    Modulo: moe_gate (Mixture of Experts)
    Funcao: Skip connections permitindo ate 150 camadas de profundidade
    Equacao: y = F(x) + x (residual connection)

24. Neural Turing Machine (NTM):
    Modulo: cag (Cache-Augmented Generation)
    Funcao: Memoria externa leitura/escrita para o pipeline RAG
    Arquitetura: Controller(RNN) + Memory Bank (read/write heads)

25. Differentiable Neural Computer (DNC):
    Modulo: meta_cognition (Meta-Cognicao)
    Funcao: Memoria escalonavel inspirada no hipocampo
    Capacidade: Similaridade, relacao temporal, freshness de dados

--- CAPSULARES / COMPETITIVAS ---

26. Capsule Network (CapsNet):
    Modulo: capsnet (Capsule Network)
    Funcao: Classificacao multi-informacional (feature + posicao + orientacao)
    Vantagem: Supera pooling de CNNs com routing-by-agreement

27. Kohonen Network / Self-Organizing Map (SOM/KN):
    Modulo: competitive (Winner-Takes-All)
    Funcao: Classificacao nao-supervisionada em 12 categorias juridicas
    Aprendizado: Competitivo, neuronio vencedor + vizinhanca se ajustam

--- ATENCAO / TRANSFORMER ---

28. Attention Network (AN) / Transformer:
    Modulo: mha (Multi-Head Attention)
    Funcao: Mecanismo central de atencao do sistema
    Arquitetura: Q*K^T/sqrt(d_k) -> Softmax -> V (7 cabecas)
    Modelos: BERT, GPT, Gemini, Claude — backbone da LLM

--- EXTRAS IMPLEMENTADOS (alem do Zoo classico) ---

29. Graph Neural Network (GNN):
    Arquivo: neural-search v17

  SymbolicOperator = {
    preconditions: Set<string>,     // predicados necessarios

    deleteEffects: Set<string>,     // predicados removidos

  function symbolicPlan(worldState, goalState):
    // Forward search com heuristica gulosa
    plan = []
    current = worldState
    while !goalState.isSubsetOf(current):
      applicable = operators.filter(op => op.preconditions.isSubsetOf(current))
      best = applicable.maxBy(heuristic: |goalState - (current + addEffects)|)
      plan.push(best)
      current = (current - deleteEffects) + addEffects
    return plan

  // Gates quanticas:
  rx(theta) = [cos(t/2), -sin(t/2), -sin(t/2), cos(t/2)]
  ry(theta) = [cos(t/2), -sin(t/2), sin(t/2), cos(t/2)]
  rz(theta) = [cos(t/2), -sin(t/2), sin(t/2), cos(t/2)]

  // Feature Maps:
  zzFeatureMap(input, nQubits):
    state[i] = input[i] * PI
    zzPhase = state[i] * state[j]  // pairwise non-linear
    state[i] += zzPhase * 0.5

  iqpFeatureMap(input, nQubits):
    // Commuting gates for quantum advantage
    state[i] = input[i] * PI
    iqpPhase = state[i] * state[j] * PI
    state[i] *= cos(iqpPhase)

  // VQC Forward Pass:
  vqcForward(input, params, config):
    state = featureMap(input)
    for layer in nLayers:
      for qubit in nQubits:
        state[q] = applyGate(rx, ry, rz, params[layer][q])
      state = entangle(state)  // CNOT between adjacent
      state = applyNoise(state, noiseModel)
    return measure(state)

  // Noise Models:
  depolarizing(state, p):    state *= (1 - p) + p * random()
  amplitude_damping(state, p): state *= sqrt(1 - p)
  phase_flip(state, p):      state *= (random() < p) ? -1 : 1

  3. TTL: 24 horas padrao, com hit counter

  function generateQueryHash(query, source):
    normalized = query.toLowerCase().trim().replace(/\s+/g, " ")
    hash = SHA256(`${source}:${normalized}`)
    return hash

  function jaccardSimilarity(a, b):
    setA = Set(a.split(/\s+/))
    setB = Set(b.split(/\s+/))
    intersection = setA ∩ setB
    union = setA ∪ setB
    return |intersection| / |union|

  function getCachedRAGResult(query, source, threshold=0.85):
    // 1. Exact hash match
    exactMatch = db.api_cache.where(hash=queryHash, source=source, expires_at > now)
    if exactMatch: return { hit: true, data: exactMatch.response_data }

    // 2. Fuzzy match (recent 50 entries)
    recentEntries = db.api_cache.where(source=source, expires_at > now).limit(50)
    for entry in recentEntries:
      if jaccardSimilarity(query, entry.query_text) >= threshold:
        return { hit: true, data: entry.response_data }

    return { hit: false }

FUNCOES PADRAO:
  sigmoid(x) = 1 / (1 + exp(-x))
  tanh(x) = Math.tanh(x)
  relu(x) = max(0, x)
  leakyRelu(x, alpha=0.01) = x > 0 ? x : alpha * x

FUNCOES AVANCADAS:
  mish(x) = x * tanh(softplus(x))           // Misra 2019, auto-regularizado
  mishDerivative(x) = exp(x)*omega / delta^2  // para backpropagation

  elu(x, alpha=1.0) = x > 0 ? x : alpha * (exp(x) - 1)   // Clevert et al. 2015
  eluDerivative(x) = x > 0 ? 1 : elu(x) + alpha

  gelu(x) = x * 0.5 * (1 + erf(x / sqrt(2)))    // Usado em BERT/GPT
  geluApprox(x) = 0.5*x * (1 + tanh(sqrt(2/PI) * (x + 0.044715*x^3)))

  swish(x) = x * sigmoid(x)                 // Usado em Gemini
  silu(x) = swish(x)                        // alias

FUNCOES QUANTICAS:
  quantumSigmoid(x) = sigmoid(x)^2          // Probabilidade de ativacao quantica
  quantumTanh(x) = tanh(x) * cos(x * PI/4)  // Oscilacao modulada para VQC
  quantumRelu(x) = relu(x) * (1 + 0.1*sin(x))  // Interferencia construtiva

SOFTMAX:
  softmax(values):
    maxVal = max(values)                     // Estabilidade numerica
    exps = values.map(v => exp(v - maxVal))
    sum = SUM(exps)
    return exps.map(e => e / sum)

 41. HEAD PRUNING (SHAP-based MHA Optimization)
================================================================================

Arquivo: src/lib/neural/head-pruning.ts (219 linhas)

REFERENCIAS: Michel et al. (2019), Voita et al. (2019)

PROPOSITO:
Analise SHAP-like de importancia para cada attention head do MHA.
Poda heads com baixa contribuicao para reduzir custo computacional.
Inclui Bayesian Uncertainty Quantification para estimativa de confianca.

ALGORITMO SHAP (Leave-One-Out):
  function computeHeadImportance(heads, scores, pruneThreshold=0.05):
    baselineScore = computeWeightedScore(allHeads, scores)
    for each head[i]:
      reducedScore = computeWeightedScore(allHeads - head[i], scores)
      shapValue = baselineScore - reducedScore
      shouldPrune = |shapValue| < pruneThreshold
    return HeadImportance[]

BAYESIAN UNCERTAINTY:
  function bayesianUncertainty(scores):
    mean, variance = computeStats(scores)
    cv = sqrt(variance) / mean  // coefficient of variation
    entropy = -sum(p_i * log(p_i))
    calibration = 1 - |mean - median| / range
    confidenceInterval = [mean - 1.96*stderr, mean + 1.96*stderr]

DYNAMIC PRUNING:
  function dynamicPrune(heads, scores, targetSpeedup=1.5):
    importance = computeHeadImportance(heads, scores)
    sorted = importance.sort(by: shapValue, ascending)
    pruneCount = ceil(heads.length * (1 - 1/targetSpeedup))
    return heads.filter(not in pruneCount lowest)

Funcoes: computeHeadImportance, bayesianUncertainty,
         dynamicPrune, computeWeightedScore

 42. OFFLINE SYNC (IndexedDB + Queue)
================================================================================

Arquivo: src/lib/neural/offline-sync.ts (173 linhas)

PROPOSITO:
Capacidade de edicao offline com IndexedDB para armazenamento local
e sincronizacao automatica quando a conectividade e restaurada.
Aproveita infraestrutura Yjs existente para resolucao de conflitos.

INTERFACES:
  PendingChange {
    id, table, operation ("insert"|"update"|"delete"),
    data, createdAt, retries, lastError
  }

  OfflineSyncState {
    isOnline, pendingChanges, lastSyncAt, syncInProgress
  }

STORAGE:
  - IndexedDB database: "rag-elp-offline"
  - Object stores: "pending_changes" (keyPath: "id"), "sync_state"

ALGORITMO DE SYNC:
  1. Detecta estado online/offline via navigator.onLine + event listeners
  2. Quando offline: armazena mudancas em IndexedDB como PendingChange
  3. Quando online restaurado:
     a. Carrega todos PendingChanges do IndexedDB
     b. Ordena por createdAt (FIFO)
     c. Para cada mudanca:
        - Tenta aplicar via Supabase (insert/update/delete)
        - Sucesso: remove do IndexedDB
        - Falha: incrementa retries, salva lastError
        - Max retries (5): marca como failed, notifica usuario
  4. Atualiza lastSyncAt e pendingChanges count

FUNCOES:
  openDB, addPendingChange, getPendingChanges, removePendingChange,
  syncAllChanges, getOfflineSyncState, initOfflineSync

 68. REINFORCEMENT FEEDBACK LOOP — REWARD LOOP (v7.3)

ARQUIVO: src/lib/neural/reward-loop.ts

  auto-otimizacao de pesos de roteamento entre providers e agentes.

FONTES DE FEEDBACK:
  - AIFeedbackButtons: thumbs up (+1) / thumbs down (-1)
  - DocumentFeedback: stars 1-5 → normalizado para range [-1, +1]

  - getProviderScore(provider): retorna score acumulado
  - getTopProviders(n): ranking dos N melhores providers
  - applyWeightUpdates(): atualiza pesos via meta-learning.ts

PARAMETROS:
  - Learning Rate: 0.05
  - Decay Factor: 0.95 (suavizacao exponencial)
  - Min Samples: 5 (antes de atualizar pesos)
  - Score Range: [-1.0, +1.0]

FORMULA DE ATUALIZACAO:
  new_score = decay * old_score + learning_rate * reward
  weight_delta = learning_rate * (reward - baseline)

 69. TASK ORCHESTRATOR COM PRIORIZACAO (v7.3)
================================================================================

ARQUIVO: src/lib/neural/task-orchestrator.ts

DESCRICAO:
  Sistema de orquestracao de tarefas com priority queue, checkpointing
  automatico e rollback cognitivo. Coordena multiplas tarefas paralelas
  (processamento de imagem + geracao de texto + busca na web).

ALGORITMO DE PRIORIZACAO:
  Shortest-Job-First (SJF) + urgencia contextual
  score = urgencia * 1.0 + contexto_emocional_ToM * 0.3 + (1/complexidade) * 0.2

FUNCIONALIDADES:
  - enqueue(task): adiciona tarefa com prioridade calculada
  - dequeue(): retorna tarefa de maior prioridade
  - executeNext(): processa proxima tarefa com checkpointing
  - checkpoint(): salva estado em localStorage a cada tarefa completada
  - rollback(): reverte ao ultimo checkpoint e tenta alternativa
  - getQueueStatus(): retorna estado da fila (pending, active, completed, failed)

CHECKPOINTING:
  - Salva em localStorage a cada tarefa completada
  - Formato: { tasks: [], activeTask, completedCount, timestamp }
  - Restauracao automatica ao inicializar

ROLLBACK COGNITIVO:
  - Se modulo falha, reverte ao ultimo checkpoint
  - Re-enfileira tarefa falhada com urgencia elevada (1.5x)
  - Maximo 3 retries por tarefa antes de marcar como failed
  - Tenta abordagem alternativa (ex: trocar provider, simplificar query)

LIMITES:
  - Max concorrentes: 3 tarefas simultaneas
  - Max fila: 50 tarefas pendentes
  - Timeout por tarefa: 30 segundos

INTEGRACOES:
  - multi-agent.ts: roteamento de tarefas para 11 agentes
  - working-memory: controle de carga cognitiva (12 slots)
  - system-health.ts: desativa tarefas nao-essenciais sob carga

 71. DISTRIBUTED TRACING (v7.3)

DESCRICAO:

  Permite explainability: "por que voce disse X?"

ESTRUTURA DE SPANS:
  {
    traceId: string,      // UUID do trace raiz
    spanId: string,       // UUID do span individual
    parentId: string|null,// ID do span pai (null = raiz)
    operation: string,    // nome da operacao
    startTime: number,    // timestamp inicio
    endTime: number|null, // timestamp fim (null = em andamento)
    tags: Record<string, string>, // metadados
    status: "ok" | "error",
    logs: string[]        // mensagens de log
  }

FUNCIONALIDADES:
  - startTrace(operation): cria trace raiz com UUID
  - startSpan(traceId, operation, parentId?): cria span filho
  - endSpan(traceId, spanId, status, logs?): finaliza span
  - getTrace(traceId): recupera trace completo com todos os spans
  - persistTrace(traceId, userId): salva na tabela orion_traces (JSONB)
  - explainDecision(traceId): reconstroi cadeia de raciocinio

TABELA: orion_traces (Supabase)
  - trace_id: text (PK)
  - spans: jsonb (array de spans)
  - created_at: timestamptz
  - user_id: uuid (FK auth.users)
  - RLS: usuarios veem apenas seus proprios traces

EXPLAINABILITY:
  - Comando: "Orion, por que voce disse X?"
  - Busca trace mais recente que contenha X
  - Reconstroi pipeline: modulos usados → decisoes → resultado
  - Retorna em linguagem natural compreensivel

MODO DEBUG:
  - Ativa via "Orion debug mode" no chat
  - Retorna pipeline completo de processamento
  - Mostra: spans com duracao, tags, status e logs
  - Visualizacao em arvore (parent-child)
